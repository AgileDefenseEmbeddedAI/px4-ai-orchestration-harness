Mission Pipeline

How It Works

Four deterministic stages from natural-language intent to physical dispatch. The LLM decomposes; the rule engine validates; a human authorizes; the transport layers execute.

Step 01
Intent Ingestion

Operator submits natural-language mission text via REST API or the authorization UI. The harness creates a mission record and begins asynchronous decomposition.

POST /intent
Step 02
Plan Decomposition

The configured LLM (GPT-4o, Ollama, or any OpenAI-compatible endpoint) parses the intent and emits a structured Mission Intent Graph (MIG): vehicles, waypoints, constraints.

MIG v1.0
Step 03
Validation & Authorization

A pure-Python rule engine checks geofence boundaries, altitude limits, RTL requirements, and airspace deconfliction — no LLM involvement. A human operator must explicitly authorize before any vehicle moves.

Human Required
Step 04
Multi-Vehicle Dispatch

Vehicle Action Lists (VAL) are dispatched per-vehicle over dual transport paths: ROS 2 uXRCE-DDS bridge for primary data, MAVLink 2 for secondary. Full audit log written before dispatch.

ROS 2 + MAVLink 2

System Design

Architecture Overview

Four modules with clean boundaries: the LLM never writes to a vehicle; the validator never calls the LLM; audit records are written before dispatch.

API Layer

FastAPI application that ingests mission intent, serves the authorization UI, and exposes the full REST interface. Manages mission lifecycle state.

  • harness/api/main.py — FastAPI app + state
  • harness/api/routes.py — REST endpoints
  • harness/api/models.py — Pydantic schemas
  • harness/ui/templates/ — Jinja2 authorization UI
Planner

LLM-backed intent decomposer that calls a configurable OpenAI-compatible endpoint. Outputs a versioned Mission Intent Graph (MIG). Falls back to a deterministic stub when no LLM is available.

  • harness/planner/decomposer.py — LLM call + stub
  • harness/planner/mig.py — MIG builder utilities
  • schemas/mig.json — MIG JSON Schema v1.0
  • config/model.yaml — provider / endpoint / model
Validator

Pure-Python deterministic constraint engine. Checks geofence (Shapely 2.x polygons), altitude bounds, RTL requirements, vehicle assignments, and airspace deconfliction. No LLM involvement — ever.

  • harness/validator/constraint_checker.py
  • config/constraints.yaml — geofence + limits
  • tests/adversarial/ — must-reject corpus
  • tests/scenarios/ — named fixture scenarios
Dispatch + Audit

Dual transport: ROS 2 uXRCE-DDS bridge (primary) and MAVLink 2 via pymavlink (secondary). Immutable append-only JSONL audit log written before dispatch. Replay tool for post-mission analysis.

  • harness/dispatch/ros2_transport.py
  • harness/dispatch/mavlink_transport.py
  • harness/audit/logger.py — JSONL audit
  • scripts/replay_mission.py — replay tool
Deterministic Safety

Hard Constraints

The validator runs these checks on every generated plan. A plan that fails any check is blocked from dispatch regardless of LLM confidence.

Constraint 01
Geofence Boundary

All waypoints must fall inside the configured geofence polygon. Checked via Shapely 2.x point-in-polygon against the WGS-84 coordinates defined in config/constraints.yaml.

Constraint 02
Altitude Bounds

Multirotor waypoints must stay between min_alt_m and max_alt_m AGL (default 5–120 m). Rover waypoints are always 0 m. Either bound violated blocks dispatch.

Constraint 03
RTL Requirement

When require_rtl: true, every vehicle must have at least one waypoint with role: rtl. A vehicle without an RTL waypoint is a hard block.

Constraint 04
Waypoint Integrity

Every waypoint ID referenced by a vehicle must exist in the MIG waypoint list. Dangling references are caught before any transport command is issued.

Constraint 05
Vehicle Assignment

A mission with zero vehicles assigned is immediately rejected. Vehicle IDs must be unique and map to the fleet defined in config/vehicles.yaml.

Constraint 06
Human Authorization

No dispatch can occur without a recorded human authorization event. The audit log captures operator identity and timestamp before the first transport command is sent.

REST Interface

API Reference

All endpoints return JSON. Run the harness locally with uvicorn harness.api.main:app --reload. Interactive docs at /docs.

Method Path Description Request Body
POST /intent Submit natural-language mission intent. Returns mission_id immediately; planning runs asynchronously. {"text": "..."}
GET /plan/{mission_id} Poll mission state. Returns full MIG, validation errors, and current status. —
POST /authorize/{mission_id} Human authorization gate. Must be called with a valid operator name before dispatch proceeds. {"authorized": true, "operator": "..."}
GET /missions List all missions with their current status. Useful for the operator dashboard. —
GET /audit/{mission_id} Read the immutable JSONL audit trail for a specific mission. Returns all recorded events in order. —
GET /docs Auto-generated interactive API docs (FastAPI / Swagger UI). Available when harness is running. —
